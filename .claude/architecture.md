# Architecture

Snapshot of the site as it exists today. For how we got here, see [refactor-plan.md](refactor-plan.md).

## Docs + blog instances
Configured in [docusaurus.config.ts](../docusaurus.config.ts):
- `developers` (default, in the classic preset) → [docs/developers/](../docs/developers/) — real content (12+ nested pages), hand-curated sidebar
- Three additional `@docusaurus/plugin-content-docs` instances registered via [src/config/doc-instances.ts](../src/config/doc-instances.ts):
  - `resources` → [docs/resources/](../docs/resources/) — index-style MDX pages, autogenerated sidebar
  - `product` → [docs/product/](../docs/product/) — placeholder (`index.mdx`), autogenerated sidebar
  - `about` → [docs/about/](../docs/about/) — placeholder (`index.mdx`), autogenerated sidebar

The classic preset's blog is wired to [docs/announcements/](../docs/announcements/) with `routeBasePath: "announcements"` so URLs live at `/announcements/*`. Three custom swizzles in [src/theme/](../src/theme/) (`BlogListPage`, `BlogPostItems`, `BlogPostPage`) render Teams-style post cards with avatars, dates, and tags.

## Sidebars
All in [sidebars/](../sidebars/):
- `developers.ts` — hand-curated tree (Mobile CI, Release Management, Bitrise Platform, Contributing) with an HTML quick-links block
- `about.ts`, `product.ts`, `resources.ts` — thin wrappers that call `autoSidebar(name)` from `shared.ts`
- `shared.ts` — one-line helper: `{ [`${name}Sidebar`]: [{ type: "autogenerated", dirName: "." }] }`

Each file is referenced by its corresponding plugin's `sidebarPath` in the config layer.

## Config layer
[docusaurus.config.ts](../docusaurus.config.ts) is ~80 lines of orchestration. Heavy lifting lives under [src/config/](../src/config/):
- `navbar.ts` — navbar items + logo, typed with `satisfies Preset.ThemeConfig["navbar"]`
- `footer.ts` — footer link sections + copyright
- `doc-instances.ts` — the three additional `plugin-content-docs` registrations
- `theme.ts` — composes `colorMode + navbar + footer + prism` into `themeConfig`

**Gotcha**: `docusaurus.config.ts` is loaded by `jiti` in Node before webpack aliases are set up. `@site/*` imports don't resolve at config-load time — use relative imports inside `src/config/`.

## Component tree
```
src/components/
  landing/           5 folder-per-component landings + primitives.ts + barrel
    primitives.ts      shared heroPatternBackground + 8 styled exports
    DeveloperLanding/  bespoke split hero
    GuidesLanding/     centered hero, deepest-bg body
    ProductLanding/    consumes all primitives; pillars + timeline
    ResourcesLanding/  primitives + flush content lane
    AboutLanding/      primitives; uses AppsHeroComponent
    index.ts
  home/              Hero, FeatureCards, ReleasePipeline, QuickLinks, FooterCta, StatsGrid (homepage sections)
  ui/                Card, Badge, AppsHeroComponent (generic primitives)
  mdx/               Callout family, Steps, Frame, PlatformCard, VideoLoop, Icon, BitrisePrereq, StageStatus, PlatformNav
  illustrations/     GuideThumbnail, GlossaryThumbnail (flat .tsx files)
  ThemeSwitcher/     runtime theme selector
```

Every component under `src/components/**` follows the convention: `FolderName/ExportedName.tsx` + `index.ts` barrel. Folder name, filename, and exported component name all match (see [conventions.md](conventions.md)).

## Theme layer
[src/theme/](../src/theme/) contains two kinds of thing:

**Docusaurus swizzles** — `BlogListPage`, `BlogPostItems`, `BlogPostPage`, `CodeBlock/Content`, `DocItem/Layout`, `DocSidebarItem/Link`, `Logo`, `MDXComponents`, `Navbar/**` (12 swizzles), `NotFound`. Each is a folder-per-swizzle (folder name dictated by Docusaurus), `ExportedName.tsx` with the code, and `index.ts` as a pure re-export. Wrapper swizzles use `WrapperProps<typeof X>` where `X` is imported from `@theme-original/...` to avoid the circular self-reference trap.

**MUI theme** ([src/theme/mui/](../src/theme/mui/)) — `palette.ts`, `typography.ts`, `core/components/*` (button, form, table overrides). Current usage is light but this layer is intentional infrastructure — MUI adoption is expected to grow.

## Styling
Three systems, scoped by where they run:
| System | Where | Purpose |
|---|---|---|
| `@emotion/styled` via [src/lib/styled.ts](../src/lib/styled.ts) | `src/components/**`, `src/pages/**` | Component-scoped styles (default choice) |
| CSS Modules (`*.module.css`) | `src/theme/**` swizzles | Docusaurus component overrides |
| Global CSS | [src/css/custom.css](../src/css/custom.css), [src/css/tokens.css](../src/css/tokens.css) | Design tokens + Infima overrides (no component rules) |

The `styled()` wrapper in [src/lib/styled.ts](../src/lib/styled.ts) accepts both HTML tag strings and React components (`keyof JSX.IntrinsicElements | ComponentType<never>`) and narrows emotion's union-confused overload resolution with a single internal `never` cast.

## Design tokens
[src/lib/tokens.ts](../src/lib/tokens.ts) is the frozen foundation: three `ThemeTokens` objects (`mcoeDefaultTokens`, `uhcTokens`, `optumTokens`) covering brand colors, surfaces, semantic colors, hero gradients, code-syntax palette, and dark-mode overrides. The data shape is approved and locked; the consumer plumbing (CSS-var generation, theme switching) is fair game.

## Routing
- Homepage (`/`) → [src/pages/_Home.tsx](../src/pages/_Home.tsx) (underscore-prefix excludes it from automatic routing) with [src/pages/index.ts](../src/pages/index.ts) as the barrel that actually registers the route
- `/developers`, `/product`, `/about`, `/resources` → flat tsx pages in [src/pages/](../src/pages/) that mount the corresponding `*Landing` component
- `/announcements/*` → blog plugin
- All doc routes → the four doc instances

Navbar uses `activeBaseRegex` for cross-instance active state. Any URL change needs the regex checked too.

## Client modules
[src/plugins/firebase-analytics.ts](../src/plugins/firebase-analytics.ts) — Firebase Analytics init. Reads `firebaseConfig` from `customFields` (sourced from [.env](../.env)). GA-only; no other Firebase services wired up.

## Deploy
[.github/workflows/build-deploy.yml](../.github/workflows/build-deploy.yml) → JFrog → UHG OOSS. No lint/typecheck/build gate in CI today; run `pnpm build` locally before pushing.
