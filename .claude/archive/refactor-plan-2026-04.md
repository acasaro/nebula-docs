# Refactor Plan

Historical record of the structural refactor that landed in April 2026. Most items are shipped; kept as a log of **what was done and why** (incl. the gotchas we hit) so future contributors and LLMs can pick up context.

**Status**: HIGH items (1–3) ✅ · MEDIUM items (4–5, 7) ✅ · LOW items (8, 10) ✅ · CI gate (6) ⏸ deferred · ESLint barrel rule (9) deferred.

> **Ground rules** (still apply going forward):
> - The site functions exactly as desired. Every refactor is **behavior-preserving**. After each change, run `pnpm build && pnpm typecheck` and spot-check the dev server.
> - Token values in [src/lib/tokens.ts](../src/lib/tokens.ts) are frozen. Consumers/plumbing can change; the data cannot.
> - MUI theme layer ([src/theme/mui/](../src/theme/mui/)) stays — MUI usage will grow.
> - No component code in `index.tsx` files. Ever.

## HIGH impact

### 1. ~~Convert every `index.tsx` with component code → `index.ts` + `ComponentName.tsx`~~ ✅ DONE
All 22 `index.tsx` files converted. Pattern: swizzle folder names kept as Docusaurus dictates, `.tsx` filename mirrors the exported component name, `index.ts` is a pure re-export. Homepage route handled via `src/pages/_Home.tsx` (underscore-prefix excludes from routing) + `src/pages/index.ts`.

Side fixes landed as part of this work:
- Swizzle self-referential `import type { Props } from '@theme/X'` → replaced with locally-defined + exported `Props` interfaces (matching `@docusaurus/theme-classic/src/theme-classic.d.ts` shapes).
- Wrapper swizzles (Logo, DocItem/Layout, DocSidebarItem/Link) — swapped `WrapperProps<typeof XType>` circular pattern for `WrapperProps<typeof X>` where `X` is the runtime `@theme-original` import.

Build passes; homepage + all routes render; no new typecheck errors introduced (and several pre-existing ones were resolved as a side effect).

### 2. ~~Consolidate sidebars~~ ✅ DONE (scope adjusted)
Original plan was a single `sidebars.ts` with all four sidebars. That doesn't work with Docusaurus — `sidebarPath` points to one file per doc instance, and a single shared file would cause every sidebar's autogenerated entries to resolve against whichever instance loaded it. Delivered instead:
- Moved the four files from repo root into `sidebars/` (`about.ts`, `product.ts`, `resources.ts`, `developers.ts`) — de-clutters root.
- Extracted `sidebars/shared.ts` with `autoSidebar(name)` helper; the three autogenerated files collapse to one import + one line each.
- Updated `sidebarPath` entries in [docusaurus.config.ts](../docusaurus.config.ts).
- Hand-curated `developers.ts` content unchanged.
- Build passes, all four doc instances render identically.

### 3. ~~Extract landing-page primitives~~ ✅ DONE (scope adjusted)
Original plan proposed one `<LandingLayout>` wrapping all five. On inspection the five landings have genuinely different hero shapes (DeveloperLanding uses a split two-row hero with an image anchor; GuidesLanding is centered with a smaller title and deeper background; AboutLanding uses `AppsHeroComponent` instead of a hero). A single `<LandingLayout>` would lose pixel-exact parity.

Delivered instead:
- `src/components/landing/primitives.ts` — single source of truth for the shared styled chrome: `heroPatternBackground` (the 3-stop gradient + pixel-pattern + dark-mode override, previously duplicated in 4 of 5 files), `HeroWrapper`, `HeroInner`, `HeroTitle`, `HeroSubtitle`, `PageBody`, `Content`, `SectionTitle`, `SectionSubtitle`.
- Each landing converted to a folder (per convention): `<Name>Landing/<Name>Landing.tsx` + `index.ts`.
- Landings import what matches; landing-specific variants stay local (Developer's split hero, Guides' centered hero + deepest-bg body, Resources' flush content lane, About's dropped-dead hero comment).
- `src/components/landing/index.ts` barrel added.

**Metrics**: ~160 lines removed from landing component code; the hero gradient/pattern string is now defined once instead of five times. Consumer import paths (`from '.../components/landing/<Name>Landing'`) unchanged — they resolve to the new folder via module resolution.

Build passes; all five landing routes render (`/developers/`, `/product/`, `/about/`, `/resources/`, `/resources/guides/`).

## MEDIUM impact

### 4. ~~Split `docusaurus.config.ts`~~ ✅ DONE
Extracted to `src/config/`:
- `navbar.ts` — navbar items + logo
- `footer.ts` — footer link sections + copyright
- `doc-instances.ts` — the three `plugin-content-docs` registrations (resources, product, about)
- `theme.ts` — composes colorMode + navbar + footer + prism into a single `themeConfig` export

Main [docusaurus.config.ts](../docusaurus.config.ts) shrinks from 207 lines to ~80, just orchestrating.

**Gotcha captured**: the Docusaurus config is loaded by `jiti` in Node before webpack aliases are set up, so `@site/*` paths don't resolve at config-load time. Used relative imports instead (`../lib/prismTheme` from `src/config/theme.ts`).

### 5. ~~Move Firebase config into src/~~ ✅ DONE
Renamed `firebase-config.tsx` → [src/plugins/firebase-analytics.ts](../src/plugins/firebase-analytics.ts) (dropped `.tsx` — no JSX in the file). Updated `clientModules` path in [docusaurus.config.ts](../docusaurus.config.ts). Build output confirms Firebase is bundled into `main.*.js` from the new location.

### 6. CI quality gate ⏸ DEFERRED
Skipped on purpose — `pnpm typecheck` has ~20 pre-existing errors, so adding it as a blocking gate would fail main. Revisit once those are triaged, or add as advisory-only. A minimal `pnpm build` gate (catches broken links + missing modules) is still a reasonable next step when you're ready.

### 7. Styling-system policy (docs only, ~30m)
Captured in [conventions.md](conventions.md). ESLint/stylelint guardrails would be additive tooling and are deferred until there's a concrete violation to prevent.

## LOW impact

### 8. ~~Fix `any` in styled wrapper~~ ✅ DONE
[src/lib/styled.ts](../src/lib/styled.ts) now uses `keyof JSX.IntrinsicElements | ComponentType<never>` with an explicit `import type { JSX } from 'react'`. The `never`-cast at the single boundary narrows emotion's overload. Zero typecheck errors in this file now (was 2 pre-existing).

### 9. Document barrel-import rule
Deferred. Convention is in [conventions.md](conventions.md); an ESLint rule is additive tooling not worth the churn until there's a violation.
