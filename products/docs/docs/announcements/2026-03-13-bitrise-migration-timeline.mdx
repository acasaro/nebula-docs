We want to clarify and correct some confusion caused by our earlier communication regarding GitHub Actions runners and the Bitrise migration timeline. First — thank you for the feedback. It's clear the dates communicated sounded more aggressive than intended, and we want to reset expectations with accurate timing.

{/* truncate */}

## What is changing (and what is not)

- The Mobile Center of Excellence is standardizing on **Bitrise** for mobile applications released through MCoE.
- Bitrise is replacing **GitHub Actions + macOS‑UHG runners** for mobile build and release workflows.
- This **does not** mean GitHub Actions are being shut down broadly, nor does it apply to non‑mobile teams or non‑macOS runners.

## Updated and clarified timeline

| Timeframe | What's happening |
|---|---|
| **Now through March** | Enablement, onboarding, and early migrations to Bitrise. No forced shutdowns. |
| **Mid‑April** | Recommended planning window for teams to schedule their migration. MCoE will actively assist teams still on GitHub Actions. |
| **By end of Q2** | `macos‑uhg` runners will be retired. Mobile apps released via MCoE must be building and releasing through Bitrise. |

<Note>
There is no mid‑March cutoff for macOS runners.
</Note>

## Why this change is happening

Bitrise provides a single, supported workflow from PR to production that replaces:

- GitHub Actions
- AWS macOS runners
- Manual artifact uploads to Firebase

This improves **reliability**, **auditability**, and alignment with the new automated mobile release process.
