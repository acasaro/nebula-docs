---
title: 'Expandable'
description: 'Flatter disclosure for nested-property documentation.'
icon: 'chevrons-down'
---

`<Expandable>` is a flatter disclosure than `<Accordion>` — used primarily for nested-property documentation in API references where you want the summary to read `Show <title>` / `Hide <title>`.

## Default closed

<Expandable title="user properties">
  <Property name="user.id" type="string" required>
    Stable identifier scoped to the parent project.
  </Property>
  <Property name="user.email" type="string" required>
    Unique within the project.
  </Property>
  <Property name="user.roles" type="string[]">
    Role identifiers granted to the user.
  </Property>
</Expandable>

## Default open

<Expandable title="post properties" defaultOpen>
  <Property name="post.id" type="string" required>
    Stable global identifier.
  </Property>
  <Property name="post.title" type="string" required>
    Free-form title.
  </Property>
  <Property name="post.body" type="string">
    Markdown body. Up to 256 KB.
  </Property>
</Expandable>

## Custom labels

<Expandable title="advanced options" closedText="Reveal" openedText="Collapse">
  - `retry.attempts` — defaults to 3
  - `retry.backoff` — defaults to `exponential-with-full-jitter`
  - `timeout.ms` — defaults to 30000
</Expandable>

## Inside a property tree

<Property name="user" type="object">
  The user record.

  <Expandable title="properties">
    <Property name="user.id" type="string" required>
      Stable identifier.
    </Property>
    <Property name="user.email" type="string" required>
      Unique within the project.
    </Property>
  </Expandable>
</Property>

<Callout type="tip">
  Use `<Expandable>` over `<Accordion>` when the disclosure is *part of* a structured field listing. Use `<Accordion>` for standalone Q&A-style content.
</Callout>
