The AcmeCloud data model has three top-level entities: **Project**, **User**, and **Post**. A project owns its users; a user authors posts; posts are addressable across projects through a stable global ID.

## Project

A project is the unit of multi-tenancy. Everything you create — users, posts, API keys, webhooks — is scoped to a project.

<Property name="project.id" type="string" required>
  Stable, opaque identifier. Format: `prj_<24 hex>`.
</Property>

<Property name="project.name" type="string" required>
  Human-readable label shown in the dashboard.
</Property>

<Property name="project.tier" type="'free' | 'pro' | 'enterprise'" default="free">
  Pricing tier. Drives rate limits, retention windows, and feature gating.
</Property>

<Property name="project.createdAt" type="string">
  ISO-8601 timestamp.
</Property>

## User

Users live inside a project. The same human can exist as separate users in separate projects — there is no global user identity.

<Property name="user.id" type="string" required>
  Stable identifier scoped to the parent project. Format: `usr_<24 hex>`.
</Property>

<Property name="user.email" type="string" required>
  Unique within the project.
</Property>

<Property name="user.name" type="string">
  Optional display name.
</Property>

<Property name="user.roles" type="string[]" default="['member']">
  Role identifiers granted to the user. Built-in roles: `member`, `editor`, `admin`. Custom roles defined per project.
</Property>

## Post

A post is a versioned content record. Posts are mutable but every change writes a new revision; the API always returns the latest unless you ask for a specific `revision`.

<Property name="post.id" type="string" required>
  Stable identifier. Format: `pst_<24 hex>`.
</Property>

<Property name="post.authorId" type="string" required>
  Foreign key to `user.id`.
</Property>

<Property name="post.title" type="string" required>
  Short, free-form title.
</Property>

<Property name="post.body" type="string">
  Markdown body. Up to 256 KB.
</Property>

<Property name="post.tags" type="string[]" default="[]">
  Free-form tags for organization. Indexed for search.
</Property>

<Property name="post.revision" type="number">
  Monotonically increasing per-post version number. Each update increments it.
</Property>

## Why no global user table?

<Accordion title="Tenancy isolation" defaultOpen>
Per-project scoping means a security incident in one tenant cannot leak into another. The price is duplication when the same human signs up to multiple projects — the model accepts that tradeoff.
</Accordion>

<Accordion title="Auth provider integration">
Each project picks its own OIDC provider. A global user would force a single auth contract; per-project users let each tenant pick their own.
</Accordion>

<Accordion title="Why not project-scoped IDs across the board?">
Posts get global IDs because cross-project sharing is a planned feature. Users do not, because cross-project membership creates a privacy surface we explicitly don't want to introduce.
</Accordion>
